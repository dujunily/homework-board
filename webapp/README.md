# 作业板 · 电脑端录入页

一个单文件网页，用来在电脑上批量布置作业。用**你自己的坚果云账号**直接读写
`/dav/作业板/`，和手机端、电视端是同一份数据——不需要本地同步文件夹，
也不依赖坚果云客户端在后台跑。

- **直连云端**：写进去立刻在云上，电视端拉到就是最新的
- **不用装 App**：一个 `index.html` + 一个本地服务，Windows / macOS / Linux 都能跑
- **批量录入**：一屏连写五条，还能切前一天/后一天，周末把一周排好

<br>

## 怎么启动

双击对应系统的入口即可。三个平台逻辑一样：起一个只监听 `127.0.0.1` 的服务，然后自动打开浏览器。

| 系统 | 双击这个 | 实际做了什么 |
|---|---|---|
| Windows | `启动-网页版.bat` | 有 Python 就用 `py -3 serve.py`；没有就用 PowerShell 版服务（`serve.ps1`，不装任何东西） |
| macOS | `启动-网页版.command` | `start.sh` → `python3 serve.py` |
| Linux | `start.sh` | 同上 |

> macOS 首次双击若提示「无法打开，因为来自身份不明的开发者」：右键 → 打开 → 再点一次「打开」。

命令行也行：

```bash
python3 serve.py            # 自动挑空端口（8123 起）并开浏览器
python3 serve.py 8123       # 指定端口
python3 serve.py --no-open  # 只起服务
```

关掉那个终端窗口即停止服务，录入过程中别关。

**为什么不能直接双击 `index.html`**：浏览器 `fetch` 带 `Authorization` 头属于非简单请求，
会先发 `OPTIONS` 预检；坚果云响应里**没有任何 `Access-Control-Allow-Origin`**（实测如此），
预检必然失败，请求根本发不出去。所以得由本机服务代跑一趟。
另外浏览器发不了 UDP 广播，通知电视也得借服务的手。

<br>

## 怎么用

1. 填三项，点「连接」：

   | 项 | 填什么 |
   |---|---|
   | 目录地址 | `https://dav.jianguoyun.com/dav/作业板`（默认，可改） |
   | 账号 | 坚果云登录邮箱 |
   | 应用专用密码 | 坚果云网页 → 账户信息 → 安全选项 → 添加应用 → 生成。**用登录密码一定 403** |

   目录不存在会自动建出来。勾了「记住密码」下次打开直接进。

2. 选科目 → 打标题 → 补充说明 → 加图 → 点「保存并同步」
3. 点顶栏 `‹` `›` 切前一天/后一天（电脑端是唯一允许改日期的端，适合周末把一周排好），
   不是今天时会出现「回到今天」
4. 保存成功后页面会调一下本地服务的 `/ping`，本机替它往局域网喊一嗓子（UDP 47823，
   和手机端同一套暗号），电视 1~2 秒内就更新——不用去动电视遥控器

图片支持 **⌘V / Ctrl+V 直接粘贴截图**，也可以一次拖入多张。

<br>

## 为什么它比手机 App 更适合在电脑上用

| | 电脑网页 | 手机 App |
|---|---|---|
| 键盘 | 一次敲五条，还能切日期预排 | 一条一条来 |
| 图片 | ⌘V 粘贴截图、一次拖多张 | 拍照或相册 |
| 同步 | 直接写云端，不需要本地客户端 | PUT 到坚果云 |
| 依赖 | 无（不引 CDN、不引字体库） | 需安装 |

<br>

## 写入规则（与手机 App 一致）

```
图片 → img/YYYY-MM-DD/<8位hex>.jpg     （长边压到 1600px，JPEG q=0.8）
     → day/YYYY-MM-DD.json             （先读，按 id 合并，再写回）
     → manifest.json                   （回写该日的 itemCount）
     → POST /ping                      （本机广播，让电视立刻来拉）
```

- **先读后合并**：不会覆盖别处写入的条目
- **未知字段原样保留**：不破坏数据契约，手机端加的字段不会被网页吃掉
- **`fileEtag` 写空串**：坚果云 `HEAD` 不回 ETag（要 `PROPFIND` 才有），
  电视端对这天降级为「每次都下载 json」（文件很小，无感）
- **写完回读校验**：重新读一次 day json，条数对不上或刚写的那条不在文件里就直接报错，
  不会静默显示「已保存」
- 图片文件名随机生成且**永不复用**；删除条目时图片保留不删（无引用，电视端不显示，不影响使用）

<br>

## 本机服务做了什么

`serve.py` / `serve.ps1` 只干两件浏览器干不了的事，都只监听 `127.0.0.1`：

| 端点 | 作用 |
|---|---|
| `/dav-proxy?base=…&path=…` | 把 WebDAV 请求原样转发到坚果云（GET / PUT / MKCOL / PROPFIND / DELETE …），`Authorization` 跟着请求走，服务端不读不存 |
| `POST /ping` | 用 `HOMEWORK-BOARD/SYNC/1` 这个暗号往 `192.168.x.255` 和 `255.255.255.255` 的 47823 连发 3 次，6 秒后再补一轮（等云端落盘） |

其余请求按普通静态文件返回。喊不出去也不影响保存，最坏退回「切回前台才更新」。

## 自测

不需要浏览器，也不需要起服务：

```bash
node test-logic.js
```

它把 `index.html` 里的脚本抽出来，配一套假 DOM + 假的 `/dav-proxy`
（请求最终落到系统临时目录里的真实文件），真的跑 `save()` / `switchDate()` / `setValidUntil()`，
检查 30 条断言——包括「不覆盖手机端写入的条目」「编辑不产生重复」「order 连续」
「manifest 的 itemCount / fileEtag 正确」「图片路径合规且不塞进 json」「切日期不影响今天」
「周五周六默认管到周日」。

## 注意

- **同一天不要在手机 App 和网页同时编辑**。两边都是「读-改-写」，几乎同时保存时后写的一方会覆盖前一方。隔开几十秒就没问题。
- **密码存在浏览器 localStorage 里（明文）**，和手机端存密码是同一水平。共用电脑上别勾「记住密码」。
- 提示「写入失败」多半是坚果云限流（303/503）或网络抖动，等几秒重试。
- 目录里的 `.DS_Store`、坚果云的冲突副本（`xxx 的冲突副本.json`）与本应用无关，可以定期清。
- 图片总量会持续增长。电视端有 200MB 缓存上限，云端目录建议每季度清一次超过 60 天的 `img/` 子目录。
